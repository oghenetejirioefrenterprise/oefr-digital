### [09:45] making_cheddar
**cciephantom:** Cron jobs are failing, they are meant to have been transitioned from openclaw to trinity with Claude agent SDK, what is the issue

**Trinity:** Root cause found and fixed. Not a Claude SDK issue at all — it was dumb cron-level.

**The bug:** Crontab uses `source ~/.profile && ... python ...` but cron defaults to `/bin/sh` (dash on Ubuntu). Dash doesn't have `source` — only `.` (dot). So every cron line exited with code 127 at the very first command, before Python ever started. That's why:
- Morpheus/Needle/Oracle/Neo logs stopped updating around Apr 16-18
- Zero telegrams landing from any scheduled agent
- Processes never showing up in `ps` — they died instantly

The crontab got modified Apr 18 15:22 (that's when someone swapped `.` for `source` or rewrote those lines). The one log entry we saw from Apr 19 05:13 was a manual debug run, not cron.

**The fix:** Added two lines to the top of your crontab:
```
SHELL=/bin/bash
PATH=/home/oghenetejiri/.local/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
```

Now cron uses bash, `source` works, claude CLI is on PATH. Verified with `/bin/bash -c "source ~/.profile && ..."` — returns `SOURCE_OK`. Ran `cron_runner.py morpheus` directly, SDK connects and starts the cycle cleanly.
